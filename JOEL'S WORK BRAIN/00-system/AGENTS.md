# Agent Instructions

Read this file before updating Joel's Work Brain.

## Mission

Maintain Joel's personal work operating system. Convert messy daily context into organized markdown files that help Joel know:

- what is active
- what changed
- what is open
- what is risky
- who is involved
- what needs attention next

## Boundaries

- Do not modify the official TA Brain `wiki/` files unless Joel explicitly asks.
- Do not modify `raw/` unless Joel explicitly asks.
- Keep Joel's Work Brain files inside `JOEL'S WORK BRAIN/`.
- Keep entries practical and operational.
- Do not invent dates, contacts, or statuses. Mark unknowns clearly.

## Standard Folders

- `01-daily-dumps/`: daily source summaries
- `02-plans/`: one file per client plan
- `03-projects/`: one file per side project
- `04-people/`: contacts and relationship notes
- `05-processes/`: reusable process lessons and checklists
- `06-reminders/`: open reminder rollups and rules
- `07-brief-sheets/`: visual brief sheet prompts and summaries
- `templates/`: reusable page templates

## Ingest Rules

When Joel provides a brain dump:

1. Preserve the date.
2. Summarize the day in `01-daily-dumps/`.
3. Update any mentioned plan pages.
4. Update any mentioned project pages.
5. Update any mentioned people pages.
6. Update process pages when Joel states a lesson or rule.
7. Add or update open items.
8. Update reminder rollups.
9. Update `index.md`.
10. Append to `log.md`.

## Status Language

Use clear states:

- `Not started`
- `Active`
- `Waiting`
- `Blocked`
- `At risk`
- `Done`
- `Resolved`
- `Watching`

## Open Item Format

Use this table:

| Item | Owner | Severity | First Mentioned | Last Mentioned | Due | Status | Reminder |
|---|---|---|---|---|---|---|---|

## Tone

Be direct, practical, and friendly. Joel likes energy, but the files should stay clear enough to scan during work.
