# Operating Rules

Use these rules whenever updating Joel's Work Brain.

## Always Do

- Preserve the date of each source dump.
- Keep updates inside `JOEL'S WORK BRAIN/`.
- Update the relevant object pages, not just the daily dump.
- Update open reminders when new open items appear.
- Move resolved items out of open lists when Joel says they are done.
- Update indexes when pages are created or status changes.
- Append one log entry for every ingest, report, review, or major edit.

## Never Do

- Do not invent contacts, dates, file statuses, or plan status.
- Do not silently overwrite conflicting information.
- Do not put personal work status into the official TA Brain wiki unless Joel asks.
- Do not let old open items vanish without a resolved note.
- Do not make every mention urgent. Use severity.

## Canonical Update Order

1. Read the source or request.
2. Identify objects mentioned.
3. Update daily dump or report source page.
4. Update plans.
5. Update projects.
6. Update people.
7. Update processes.
8. Update reminders.
9. Update indexes.
10. Update log.
11. Summarize what changed.

## Unknowns

If something is unclear, write `Unknown` instead of guessing.

If a name is uncertain, write the best heard spelling and note that it is uncertain.

## Stale Items

An item is stale when it is still open and has not been mentioned inside its reminder window:

- S1: same day
- S2: next business day
- S3: 2-3 business days
- S4: weekly review

## Report Discipline

Reports should be useful artifacts, not summaries for their own sake.

Every report should answer:

- What changed?
- What matters now?
- What is stuck?
- What should Joel do next?
- What can be ignored?
