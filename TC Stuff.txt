"	TRANSITION MANAGER (TM )"

Position Summary 
The Transition Manager (TM) is responsible for leading plan conversions to Transamerica and acts as the central coordinator, or project manager for the entire conversion project. The TM is the project team leader who is ultimately responsible for client satisfaction throughout the conversion.  

Responsibilities

Meetings/Conference Calls
"	New Sale Call- within 3 days of the New Sale Announcement schedules a conference call with the Sales team and the Pricing Consultant to gather information about the new client and the services offered during the sales process."
"	TM Welcome Call- within 2 days of the New Sale Call, coordinates with the Sales Team and/or Client Executive to schedule an introductory call whereby they are introduced to the client for the first time.  "
"	Introductory e-mail – within 1 day of the TM Welcome Call, e-mails the client with an introductory package containing contact information, required documents, and the project plan. "
"	Weekly Client Calls - within 5 business days of the Welcome Call, establishes a weekly conference calls schedule. The meetings are designed to; provide the client with updates related to project status, manage expectations related to target dates and discuss overall project scope. The TM distributes meeting agendas and timelines at least 24 hours prior to meetings. The TM distributes meeting minutes within 48 hrs following the meetings. "
"	Internal Team Meetings - within 5 business days of the Welcome Call, establishes a weekly meeting schedule. The meetings are designed to; gather key project team members to inform them of new developments, review plan design, obtain updates on project status, address any project risks or missed deliverables and develop the agenda for the next Client Call.  "
"	Implementation Meeting – This meeting is scheduled after the Prior Plan Review (PPR) has been completed and is typically held on-site with the client, but can be conducted via conference call if appropriate. The TM creates the Implementation Manual (including PPR) for the meeting and the CE coordinates scheduling/logistics with the client.  The TM distributes detailed minutes within 3 days of the meeting."
"	Prior Vendor Questionnaire Call- within 2 business days of obtaining prior vendor contact information, coordinates with the Data Consultant to schedule a call with the client and prior vendor to review the Questionnaire. "

Project Team Responsibilities and Oversight
"	Creates and maintains the project plan. "

Setting up bonus as a separate election
1)	It is important that when setting up a separate bonus election that the sources are in a specific order. The regular deferral sources should be the first set of sources and the bonus deferrals should follow.  
2)	The regular Roth deferral should always be combined with the regular pre-tax deferral. The Roth bonus should be combined with the pre-tax bonus. The combined min/max on the pre-tax sources should always be N/A. 
3)	By combining the regular deferrals with each other and the bonus deferrals with each other this allows the deferral groups to have their own min/max. With the deferral groups set up this way the participant can elect a regular deferral that can be up to the total plan limit and still elect a separate bonus deferral. For example, a participant can have a 6% pre-tax deferral and still elect to defer 100% of their bonus. Even though the total exceeds 100% since the min/max are separated a participant can elect up to the plan deferral limit separately. If the plan max is less than 100%; i.e. 80%; the participant would be able to enter in up 80% on each set of sources.

##Source Mapping Procedures
#

1)	DC identifies all sources with balances at the current vendor, saves the information in a spreadsheet within the account folder and notifies the TC that the spreadsheet is ready for their updates.
2)	TC reviews the sources on the spreadsheet and identifies the sources from the prior plan review, noting the attributes of each source within the spreadsheet.  The attributes will be defined as source name to be mapped to at Diversified, contribution type code, frequency of contribution, withdrawal provisions and vesting.  
3)	For sources that are not identified in the prior plan review (I.e. frozen sources), the TC asks the DC to check with the prior vendor to obtain the attributes. 
4)	Based on the information provided from the DC, the TC then updates the spreadsheet with the findings and shares the completed information with the TM. 
5)	If the DC receives an additional “admin” contact at the prior vendor to request this information from because they do not have it themselves, the TM will be responsible to contact that individual.
6)	The TM reviews the information with the client and obtains their approval/confirmation on the source mapping.  The approval/confirmation should be documented in e-mail, or weekly meeting minutes.  
7)	If there were any updates, the TM/ TC should note these in the source mapping spreadsheet.  The TM shares the client confirmed source mapping with the TC, DC and Plans Consultant.  This is what the DC will use to map sources when conversion records are received.

##Payroll File Automation Set Up Guide

The IM Payroll Automation? field on the Remittance Home page in Paris 3 must be set to 'Yes' to enable payroll file automation for automated PSD and automated FTP clients. 
This field can be updated by the following P3 users:  Account Consultant/Account Admin, Call Center Associate, Cash PC Specialist, Contract Plan Services and Product Support. 
The field only displays for IM clients.

 

When the IM Payroll Automation? field is set to 'Yes', then the IM PSD Error Correction? field becomes enabled and a value must be selected for automated PSD and automated FTP clients. 
A value of 'TA Handles Errors' means that the account manager will be working with the client to resolve data errors that are generated by the client's file. This value will result in the AWD error report being sent to the client's account manager. 
A value of 'Client Handles Errors on PSD' means that client will go into PSD to resolve data errors that are generated by the client's file. This value will result in the AWD error report being sent to the end queue with a status of EDSCOMPL.
The default value when the IM Payroll Automation? field is set to 'Yes' is 'Client Handles Errors on PSD'.

 

When the IM PSD Error Correction? field is set to a value of 'Client Handles Errors on PSD', then the IM Payroll Automation? field becomes disabled. 
If the value in the IM PSD Error Correction? field is switched to 'TA Handles Errors', then the IM Payroll Automation? field becomes enabled again.

 


Automated PSD clients and automated FTP clients must have at least one layout in EDS with the PSD Availability? field set to 'Yes'. 
Only layouts with the PSD Availability? field set to 'Yes' will be available for use by automated clients.

 

To set the PSD Availability? field set to 'Yes', go into the layout that you want to set up for automation by clicking on the layout name in EDS and then select a value of 'Yes' for the PSD Availability? field.

For PSD Automated plans only:
One user at the plan sponsor will need to be set up with all of the PSD Automated Payroll File Access permissions so that they can delegate permissions to other Plan Sponsor users.
 
To set up a plan sponsor user with the permissions go to the User Maintenance tab and under User Roles and Options for the given user, select all options under the Automated Payroll File Access heading.

At this point the set up for automated PSD clients is complete. For automated FTP client proceed with the following setup:

The File Layout Name dropdown will be populated with all file layouts for the given plan that have a PSD Availability value of Yes in the EDS Layout Screen. 
If no layouts are set up in EDS for PSD Availability = Yes, then Select: will be the only value in the File Layout Name dropdown, indicating that Layouts need to be set up for PSD Availability in EDS.

Selection of an Apply button on the Add/Edit FTP Automation screen will close out of the Add/Edit FTP Automation screen and return the user to the Remittance Home page.
 
If a field has not been populated or a valid selection made when the user selects apply, then the message: Invalid values entered will display on the screen and a red X will be placed by the field(s) that need to be corrected.

If the file name already exists in the database or in the FTP Automation Summary when the user selects Apply on the Add/Edit FTP Automation screen, then the system will display the following message in red in the lower left corner of the Add/Edit FTP Automation screen: Unable to apply requested changes, File name must be unique.
