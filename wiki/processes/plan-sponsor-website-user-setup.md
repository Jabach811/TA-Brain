# Plan Sponsor Website User Setup

Process for plan sponsor access and user setup on the Plan Sponsor Website.

## Overview

The Plan Sponsor Website gives plan sponsor users access to reports, participant information, payroll/remittance submission, and user administration. TC materials treat PSD training and user setup as part of administrative readiness.

> [!warning] Source status
> The source references screenshots that are not included. Validate current Plan Sponsor Website navigation and permission labels before using as live instructions.

## Trigger

The process is needed when a plan sponsor contact needs website access, especially during conversion setup, payroll automation, or divisional access configuration.

## Steps

1. **Confirm sponsor access need.** Owner: TC/COM. Determine which plan sponsor users need access and what privileges they should receive.
2. **Access Plan Sponsor Website.** Owner: Plan Sponsor / TC support. Navigate to the Plan Sponsor Website.
3. **Open user maintenance.** Owner: Plan Sponsor admin / TC support. Use User Maintenance to add or update users.
4. **Assign privileges.** Owner: Plan Sponsor admin / TC support. Grant the administrative privileges appropriate for the user, including payroll/remittance or automated payroll permissions where needed.
5. **Configure division access if applicable.** Owner: TC / Plan Sponsor admin. For divisional plans, limit users to the correct division/security access.
6. **Verify access.** Owner: TC / Plan Sponsor. Confirm the user can see the intended plan, division, reports, and payroll functions.
7. **Document setup.** Owner: TC. Note access decisions in plan documentation or case notes where relevant.

## Handoff Points

- TC supports sponsor training and setup.
- Plan Sponsor owns delegated user administration once the correct primary user exists.
- Payroll automation may require one sponsor user to receive all Automated Payroll File Access permissions.

## Failure Modes

- Sponsor user has access to the wrong division or too much plan-level reporting.
- Automated payroll permissions are missing, preventing file submission or delegation.
- User setup is completed but not documented for ongoing support.
- PSD access is assumed complete before actual sponsor login is verified.
