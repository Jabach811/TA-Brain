# TC Stuff

Mixed legacy source bundle containing team charters, TC/QC role definitions, go-live controls, case note template language, plan setup procedures, division/affiliate guidance, payroll automation setup, CPMA setup, and Plan Sponsor Website user setup notes.

> [!warning] Source status
> The file itself says multiple charter sections are outdated and need full QC. Treat this source as institutional memory and role/process evidence, not as current official procedure unless confirmed against current standards.

## Summary

`TC Stuff.txt` is not one procedure. It is a stitched collection of older conversion materials. The most useful wiki value is the way it fills gaps around the Transition Consultant role, Quality Control role, DDOL/VRU/PSD activation, go-live controls, case note structure, and plan administration setup.

The source is especially valuable because the existing wiki had TC and QA/QC mostly documented from the DC perspective. This file gives a broader implementation-team view of what TC and QC actually own.

## Key Claims

- The TC owns administrative setup and continuity during conversion: case notes, special procedures, remittance/admin manuals, PSD training, DDOL/VRU/PSD activation, audit controls, source mapping support, and closeout handoff.
- QC owns a structured audit/control role: participant-level conversion records and assets, mapping review, default allocations/deferrals, census details, duplicate SSNs, loan analysis, statements, participant website test IDs, and financial-risk checks.
- The team charter material describes four project modes: DC plan conversions, start-up projects, external mergers, and internal mergers.
- Several procedures are actionable but need current validation: adding divisions, divisional PSD reporting, multiple affiliates, go-live checklist, bonus election setup, source mapping procedure, payroll file automation, CPMA setup, case notes, and Plan Sponsor Website user setup.
- The go-live checklist treats limited access and full access as separate gates, each requiring system checks, case note updates, communications, access-code/service validation, and audit signoff.
- Case notes are a structured operating record, not casual notes. The template includes special alerts, conversion dates, limited access windows, CPMA/Financial Guide language, asset gathering, deferrals, loans, money sources, web portal notes, withdrawals, and archived notes.
